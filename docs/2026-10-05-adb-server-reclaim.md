# 项目 ADB 服务端来源修复

## 原因与修改

项目脚本原来只固定 SDK 客户端和 5038 端口。本轮 `server-status` 发现该端口实际由 OPPO 的 ADB 36.0.1 服务占用，配对密钥位于 SYSTEM 账户目录。ADB 的兼容协议不会因客户端路径不同而自动替换已有服务，所以固定端口后仍可能读到另一套配对状态。

`scripts/Invoke-Adb.ps1` 现在在发送项目命令前核对服务端可执行程序及用户密钥目录；发现来源不符时只停止 5038 服务，再由 SDK 接管。接管后再次核对，若端口再次被占用则明确失败，不发送安装等后续命令。`help/version/kill-server` 不触发该检查。仍保留无线连接输出和退出码的既有校验。

## 已验证

- 当前 5038 使用 SDK ADB 37.0.1 和当前用户密钥目录。
- 在无在线项目设备时，用 OPPO 二进制临时启动 5038 服务，分别从 PowerShell 7 和 Windows PowerShell 5 调用项目入口；两次均检测到不同来源并恢复 SDK 服务。
- 普通 `devices`、`server-status`、`mdns services` 在两种 PowerShell 入口中执行；修复后旧手机端口仍拒绝连接，不能以服务端修复代替设备连接成功。
- 后续读取到 PLJ110 在线及新的 mDNS 端点。签名包完成后显式重连该端点，通过 5038 覆盖安装成功，输出 `Performing Streamed Install` / `Success`；未启动应用。

仅记录必要状态摘要，不包含密钥内容或用户数据库。设备是否在线及安装结果以最终 ADB 输出为准。
