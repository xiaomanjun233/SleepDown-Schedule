# 普通版与实验版分支、版本及发布规范

本文定义 SleepDown 普通版、Beta 和实验版的共同基线与发布边界。实验代码在普通版基线上集中存放，由实验构建开关启用，便于将来制作商店版时删除。

## 1. 产品与代码基线

- `main` 是普通版唯一基线，正式版、普通 Beta 和通用修复最终都必须进入 `main`。
- `exp` 保留已发布实验版历史；新的实验功能从 `main` 基线开发，普通构建关闭实验开关。后续若继续维护该分支，应先同步 `main`。
- 普通版与实验版保持相同的 `applicationId`、Room 数据库、备份格式和发布签名。两者可以覆盖安装并共享用户数据，不创建 `.exp` 包名，也不用卸载换版。
- 普通功能不得只在 `exp` 修复后长期滞留。普通构建只运行公共通知逻辑；实验构建才显示厂商模式并注册课程组件 Provider。
- 数据迁移、导入导出、通知、Widget 和公开 Intent / Provider 协议继续遵守全局兼容要求。实验功能不能用清库、换包名或换签名规避兼容问题。

## 2. 分支职责与同步方向

| 分支或提交类型 | 内容 | 合并方向 |
| --- | --- | --- |
| `main` | 普通版基线、通用功能、普通 Beta 已验证内容、正式修复 | 先进入 `main`，再由 `main` 合入 `exp` |
| 普通功能分支 | 面向全部用户的功能或修复 | PR / 合并到 `main`，不得以 `exp` 作为唯一落点 |
| `exp` | 已发布实验历史与后续候选版本 | 接收 `main`；不将历史分支整支反向合入 `main` |
| 实验专项提交 | 厂商通知模式、导出 Provider、WakeUp 兼容壳、诊断和实验更新通道 | 以隔离提交进入公共基线；普通构建保持关闭 |

同步按以下顺序执行：

1. 普通 Beta 或普通功能先完成验证并合入 `main`。
2. 确认 `main` 可独立构建普通 Release，且不依赖 ColorOS 实验组件。
3. 需要维护 `exp` 时再合入 `main`，解决冲突后验证普通基线与实验差异。
4. `exp` 发布后继续保留为长期分支；下一轮仍从新的 `main` 向 `exp` 同步。

公共修复优先在 `main` 完成，再合入 `exp`。实验功能放在 `feature/experimental/`、`feature/coloros/`、`app/src/exp/`、`coloros-wakeup-proxy/` 等独立文件；公共通知与设置代码只保留接入钩子。一次修改同时包含公共问题和实验问题时，应拆成可独立回退的提交。

公开标签发布后不重写 `exp` 历史、不强推分支、不静默移动标签。确需修订已发布实验包时，使用新的实验序号和新标签。

## 3. 功能隔离

厂商通知模式必须同时满足以下条件才可出现和运行：

- 构建类型为 `exp`，即 `BuildConfig.SLEEPDOWN_EXP_BUILD=true`；
- 设备检测属于对应厂商；用户在“通知样式”中主动选择实验模式；
- OPPO / 一加 / realme 提供普通通知、实时活动、流体云、流体云+实时活动；荣耀提供普通通知、实时活动、YOYO建议+实时活动；小米 / Redmi / POCO 提供普通通知、实时活动、超级岛。

普通版从 `main` 的 `release` 构建，不能显示实验功能、诊断或实验更新通道，也不能依赖课程组件才能正常运行。单独选择流体云时关闭 SleepDown 自身的课程实时活动；组合模式和荣耀 YOYO 建议同时保留实时活动。小米超级岛通过原生通知扩展参数尝试显示，需澎湃 OS 3、对应焦点通知权限及小米服务开通；系统未开放时继续显示实时活动。

小米客户端方案采用 [小米官方开发指南](https://dev.mi.com/xiaomihyperos/documentation/detail?pId=2131)。实验构建可用 `sleepdown.xiaomiSuperIslandAppId` Gradle 属性或 `SLEEPDOWN_XIAOMI_SUPER_ISLAND_APP_ID` 环境变量注入已开通服务的 App ID；未配置时“超级岛”模式仍保留普通实时活动，但不附加岛参数。设备白名单、场景审核及正式权限按 [接入流程](https://dev.mi.com/xiaomihyperos/documentation/detail?pId=2132) 办理。

实验数据仍由 SleepDown 作为唯一事实来源。兼容组件只负责按 WakeUp / ColorOS 约定提供系统读取入口，不维护第二份课表。当前对外课程链路固定为课表列表、今天课程、明天课程三个读取入口；改变路径、字段或时间语义时，主应用、组件和契约测试必须同步更新。

## 4. 版本命名与 Android 版本号

所有渠道共用 `MAJOR.MINOR.PATCH` 主版本：

| 渠道 | `versionName` 示例 | Git 标签 | Release 属性 |
| --- | --- | --- | --- |
| 正式版 | `1.2.6` | `v1.2.6` | 非预发布，可成为 latest |
| 普通 Beta | `1.2.6_beta9` | `v1.2.6_beta9` | 预发布，不替换正式 latest |
| 首个实验版 | `1.2.6-exp` | `v1.2.6-exp` | 预发布，不替换正式 latest |
| 同主版本后续实验版 | `1.2.6-exp2` 至 `1.2.6-exp4` | 与 `versionName` 同名并加 `v` | 预发布，禁止覆盖旧标签和旧附件 |

规则如下：

- 实验版不使用 `_betaN` 后缀。`exp` 名称从当前普通版主版本派生，不能另起一个与普通版无关的版本线。
- 同一主版本的首次实验发布使用 `-exp`；修订发布从 `-exp2` 递增。每个公开版本都有独立标签、更新日志和 APK，不通过替换旧附件冒充原版本。
- 同一主版本下普通版、Beta 和实验版使用相同 `versionCode`，以便相同签名的渠道包相互覆盖安装。进入新的主版本或 Android 分发渠道要求更高代码时统一递增；任何公开 APK 的 `versionCode` 不得低于已安装用户可能持有的值。
- 包名和签名证书必须一致。构建后同时检查 `applicationId`、`versionName`、`versionCode` 和证书指纹，不能仅凭文件名判断版本。
- 当前 Gradle 以普通版 `sleepDownVersionName` 为主版本来源，`exp` 构建去掉 Beta 后缀后生成实验名。新增 `-expN` 发布时必须显式更新实验序号及更新器测试，不能继续产出与旧版相同的 `versionName`。

## 5. 应用内更新通道

- 普通正式版只能选择正式更新；普通版现有 Beta 开关只能接收正式版与非实验预发布，必须排除所有 `exp` 标签。
- 用户第一次获取实验版时，需要从发布页手动下载安装，普通版不能主动推荐或自动跳转到实验版。
- 只有已安装的实验构建显示“正式版 / Beta 版 / 实验版”选择器：
  - 正式版：只接收非预发布版本；
  - Beta 版：接收正式版与普通预发布，但排除实验版；
  - 实验版：只接收 `exp` 版本，不自动跨到正式版或 Beta。
- 用户从实验版切回普通版后，普通构建不再显示实验通道。再次进入实验版仍需手动安装，这是有意的进入门槛。
- 同一个 Release 同时包含主应用和课程组件时，应用更新只能选择主应用 APK；文件名含 `coloros-course-component` 或 `wakeup-proxy` 的附件必须排除，避免把组件误装成应用更新。

## 6. ColorOS 课程组件版本

- 课程组件使用独立包 `com.suda.yzune.wakeupschedule`，版本线与 SleepDown 主应用分开管理；当前兼容基线为 `6.0.17` / `versionCode 257`。
- 壳版本必须高于已验证不工作的 `6.0.12`，并满足主应用声明的最低 `versionCode`。接口或安装包行为变化时递增组件版本，主应用最低版本、诊断文案和契约测试一并更新。
- 实验 Release 必须同时附带主应用 APK 和课程组件 APK。应用内“安装课程组件”从 Gitee 的该 Release 下载组件，不在仓库内提交 APK。
- 组件包名会与官方 WakeUp 课程表冲突。检测到官方应用时只提示冲突，不自动卸载、覆盖或清除其数据。

## 7. 构建、验证与发布

普通版使用：

```powershell
.\gradlew.bat assembleGithubRelease --console=plain --no-parallel --max-workers=2
```

实验版同时构建：

```powershell
.\gradlew.bat :app:assembleGithubExp :coloros-wakeup-proxy:assembleRelease --console=plain --no-parallel --max-workers=2
```

每次实验发布至少完成：

1. 与 `main` 对比差异，确认实验功能集中在独立目录且普通构建开关关闭；普通版的新提交已经同步。
2. 运行厂商通知适配、ColorOS 映射、Provider 契约、版本解析和 Release 选择的定向测试。
3. 完整构建签名的实验 APK 与课程组件，核对包名、版本号、最低系统版本及签名。
4. 更新应用内日志和独立发布说明；GitHub、Gitee 均以预发布创建同名标签。
5. 上传 `SleepDown-Schedule_v<version>.apk` 和 `SleepDown-ColorOS-Course-Component.apk`，从公开地址回读大小与 SHA-256。
6. 实机检查组件状态、三项课程读取、测试课程的创建/删除、真实课表变更后的自动刷新，以及强行停止、重启解锁和无后台进程等边界。

实验版验证不能替代普通版验证；普通版发布也不能沿用实验版 APK。任何一条渠道的实机结果都只代表对应构建和对应设备。

## 8. 转正、暂停与回退

- 实验功能向普通版开放必须是明确的产品决定。源文件进入公共基线不代表功能转正；开放前仍需验证各厂商设备、组件分发和普通用户界面。商店版可删除实验目录、`app/src/exp/`、组件模块与公共入口钩子。
- 实验暂停时保留 `exp` 分支、历史标签和已发布附件；可停止新发布，但不删除可复现的历史版本。
- 出现数据、签名或覆盖安装风险时停止发布。功能故障优先在新的 `expN` 修订版修复，不覆盖旧 Release；必要时在发布页标明旧版问题和推荐版本。
- 从实验版切回正式版不得清除用户课表或设置。实验专属设置在普通版中保持休眠，不影响普通通知行为。
