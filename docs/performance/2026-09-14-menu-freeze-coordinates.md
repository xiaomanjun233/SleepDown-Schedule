# 三点菜单与冻结玻璃的位置更新

日期：2026-09-14。用户反馈右上角三点菜单打开弹窗时卡顿，要求继续优化玻璃、动画和冻结链路。本轮同时检查菜单本身及其后续目的弹窗，保留已有模糊、缩放、形变轨迹和课程材质。

## 代码中确认的额外开销

- `DrawBackdropNode.onGloballyPositioned` 对同一个可变 `LayoutCoordinates` 使用 `neverEqualPolicy` 反复赋值。外层布局或缩放产生位置通知时，会让背景玻璃重新采样。根 `GraphicsLayer` 保留的是子 RenderNode 引用，跳过根 `drawContent` 并不能阻止这些节点各自失效。
- `homeCaptureFrameKey` 包含 `homeMenuSourceHidden`，但菜单位于首页录制层之外。目的弹窗在 Opening 第一帧后隐藏原菜单时，会错误触发整张首页及模糊引用层重新录制。
- 三点菜单的 `showSurface` 原先等待透明度大于 `0.005` 才挂载玻璃、文字和操作项，把首次组合、测量与材质节点创建放在运动过程中。
- 菜单目的弹窗的源菜单副本在组合阶段读取动画高度；教务悬浮控件也在组合阶段读取动画透明度，造成不必要的逐帧重组。

这些是代码路径中确认的工作量，不是实机采样得出的掉帧占比。

## 本轮修改

- 公共玻璃入口增加稳定的位置冻结谓词，仅由首页 underlay 提供。已完成且匹配当前场景键的缓存可忽略位置通知；新的坐标节点、窗口/字体/配置等场景变化仍会正常刷新。前景菜单与弹窗保持实时采样。
- 谓词通过稳定引用读取，不让冻结状态变化重建整套材质或 Modifier。绘制阶段观察冻结与场景键，解除冻结时更新现有采样层。没有增加截图、像素读回、材质卸载或恢复队列。
- 移除菜单隐藏标志对首页缓存键的影响；真实按钮可见性、课表内容、配色和窗口尺寸仍属于缓存键。
- 三点菜单在 Preparing 挂载最终尺寸的实际内容和材质，以 `0.001` 的表面透明度提交预备绘制，再沿原曲线展开。原有材质节点保持到本次菜单退出完成；输入仍由原有阶段与手势规则控制。
- 菜单准备回调只表示绘制命令已录制，不代表 GPU 已完成工作。优先复用已有背景准备帧，额外等待最多三个帧回调，取消沿用原请求协程生命周期。
- 菜单表面的 `fillMaxSize` 已确定尺寸，移除重复的动画高度参数读取；教务悬浮控件的透明度读取移到图层属性阶段。
