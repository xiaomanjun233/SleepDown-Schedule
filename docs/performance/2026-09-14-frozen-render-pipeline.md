# 首页冻结渲染链路跟进

日期：2026-09-14。用户确认 beta6 的冻结有改善，但动画仍有小掉帧。本轮保留背景模糊、缩放和现有课程材质。

## 代码中确认的额外工作

- `HomeBackgroundBlurLayer.drawWithContent` 读取逐帧模糊进度，即使语义场景未变，也会使该绘制回调随动画失效。
- Closing 在模糊进度降到 0.42 时，从半分辨率模糊切回全分辨率模糊，动画中途改变处理面积和效果目标。
- 根详情转场录制普通可见帧后又调用 `drawContent`，同一内容重复遍历。清洁遮罩录制与正常可见帧不同，必须保留单独绘制。

以上是代码层面的工作量分析，不是对用户设备掉帧主因的实测归因。

## 当前实现

- 模糊半径、透明度只在 `graphicsLayer` 的属性更新阶段读取动画值。冻结绘制回调只依赖冻结状态、场景标识和窗口尺寸；重放列表不因模糊进度主动失效。
- Preparing 即录制清晰与半分辨率模糊两个引用层。清晰引用层仅取 0/1 透明度并使用 Auto 合成；共享原有完整场景，不生成另一份全屏图片。模糊层不再在第一个非零模糊帧才录制，GPU 效果的首次实际绘制仍可能有成本。
- Opening/Closing 始终使用同一个半分辨率模糊目标。模糊强度高于约 2.06dp 时保留现有分级半径；低于该值时保持这个小半径，并连续降低模糊层透明度，露出原始全分辨率场景。清晰端点不经过放大的低分辨率画面。这个小范围的混合近似代替了原先的全分辨率小半径模糊，需要实机确认观感。
- 半分辨率像素尺寸取整后，使用实际横纵比例映射回源尺寸，避免奇数窗口尺寸造成两个画面对不齐。
- 详情转场记录普通可见帧后直接绘制刚录好的 GraphicsLayer；清洁遮罩帧仍另画正常内容。
- 个性化实时预览、离散颜色更新、复制与删除落点沿用已有失效规则。课程 Composition/材质节点不卸载，不新增 Bitmap 读回、模糊金字塔或结束后的卡片重建。

GPU 仍需处理前景玻璃和变化的模糊效果。这次减少的是背景绘制失效、重复内容遍历和关闭时的大面积模糊交接，不保证消除所有掉帧。
