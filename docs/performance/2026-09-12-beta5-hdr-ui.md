# Beta5：按能力启用 HDR 课程轮廓光

基于 `abf095b`，回应轮廓光不够亮、支持时启用 HDR UI、不支持时自动降级的要求。HDR 实现为 `9e8c1d2`，顶栏范围跟进为 `dd429a5`。

本文记录首版 2.0 headroom 的交付。后续上下边缘、1.2 比率、保留色相及编辑器停用方案见 [HDR 色彩跟进](2026-09-12-beta5-hdr-hue.md)。

## 能力与生命周期

- 只在首页 MainActivity 的玻璃课程卡、轮廓光和壁纸同时启用时申请 HDR。其他 Activity、独立窗口、预览默认保持普通颜色路径；未添加设置项或修改数据格式。
- 条件是 Android 15 / API 35 及以上、硬件加速、当前屏幕支持 HDR、屏幕与窗口配置支持广色域，并且 `Display.isHdrSdrRatioAvailable` 为真。仅支持 HDR 视频不足以通过条件。
- 本地 Android 36.1 SDK 的 `ViewRootImpl.updateColorModeIfNeeded` 显示：缺少 HDR/SDR 亮度比能力会将 HDR 降为 WCG，窗口不支持广色域会进一步降为普通颜色模式；入口沿用这些条件。实际系统仍可能因亮度、温度或显示策略收缩可用亮度范围。
- 满足条件时请求 `Window.colorMode = COLOR_MODE_HDR` 和 `desiredHdrHeadroom = 2f`，只限定期望 HDR / SDR 白亮度比，不写屏幕亮度、峰值尼特数、刷新率或 OEM 私有开关。
- 显示能力变化和 View 挂载时重新判断，普通显示回调不会重复设置窗口；配置变化、关闭轮廓光或销毁页面会撤销监听并恢复原窗口参数。翻页、模糊卸载、弹窗形变的每帧状态不参与模式切换。

## 绘制

- 普通路径继续按课程颜色做 Screen 提亮，日/周视图及两种玻璃风格共用。顶部与两侧网格峰值 alpha 从 0.20 小幅提高到 0.28，侧边宽度仍是顶部的 55%，不增加模糊。
- HDR 保留普通彩色光，在原装饰层加一份更窄的缓存网格光芯。光芯同时覆盖底边，沿真实卡片形状裁切，使用平滑衰减；网格和画笔只在几何、颜色或能力变化时重建。
- Compose 1.11.2 的 `Vertices` 会把颜色转成 ARGB8；因此顶点只携带白色及透明度，真正的 HDR RGB 放在 Android long-color `LinearGradient` shader 中，色彩空间使用 `LINEAR_EXTENDED_SRGB`。没有将超白 RGB 交给 `toArgb()`。
- 光芯通道为 `1 + linearCourseChannel × (headroom - 1)`，限制在 1–2，以 SrcOver 合成；各通道不低于 SDR 白，避免浅色壁纸出现暗边。普通彩色光保留原来的课程色相，光芯增加对应颜色的亮部。
- 新增的是缓存网格绘制，不增加 CPU 截图、玻璃消费者、采样、RenderEffect 或独立 SurfaceView。HDR 窗口仍可能使系统选择更高精度的渲染目标，不能据此声称零 GPU/带宽成本或已达到 120 FPS。

系统渲染格式参考 [AOSP SkiaPipeline](https://github.com/aosp-mirror/platform_frameworks_base/blob/main/libs/hwui/pipeline/skia/SkiaPipeline.cpp)：HDR 格式由设备能力选择，包含浮点或扩展传递函数路径。设备最终色彩映射与缓存目标格式由 HWUI 决定，代码检查不等同于真机亮度验证。
