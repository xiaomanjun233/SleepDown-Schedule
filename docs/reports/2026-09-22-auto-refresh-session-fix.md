# 自动刷新登录回归与学校入口核对

日期：2026-09-22。普通版 main / 1.2.6_beta9；不更新 exp。

## 回归原因与修改

用户报告西南大学旧版本能识别登录，新版本点击读取登录态却出现导入流程。旧实现从 `https://jw.swu.edu.cn/sso/zllogin` 进入，等待教务课表页后保存会话；通用化后改用了官方导入目录的门户入口 `https://i.swu.edu.cn/`，按钮仍调用 `loginAndRefresh`，在可见页面运行官方适配器，并在导入课表后才保存配置。更换按钮文案没有改变这条调用链。

本次恢复西南大学旧 SSO 入口与课表页判断，补回门户、教务、统一认证及 IDM 的已知 Cookie 作用域。可见页面负责学校登录与凭证采集；连接操作在独立 WebView 恢复会话，复用官方适配器与 bridge 验证接口，成功后只加密保存连接配置。验证期间生成的 ImportDraft 不写入课表。手动及定时刷新仍通过原有导入接口写入指定课表。

上游提示“开始导入”的介绍弹窗由桥接层确认。已有学期、校区等选择按文本复用；西南大学、江苏大学首次连接采用官方脚本从教务页读取的当前学年、学期默认项。不能推断的必要选择仍交给用户，原选项消失时不静默切换。取消连接与页面关闭释放后台 WebView；加密保存失败不会显示已连接。

错误弹窗按错误标题识别，不再因正文出现“错误”“无法”等词直接终止。江苏大学正常的作息提示包含“如有错误请手动修改”，集中实践课说明包含“无法自动导入”，这两种说明均不代表会话失败。真正的“拉取失败”“未找到课程”等错误仍中止校验。

## 其他学校是否需要同样处理

核对对象为现有 130 所学校、142 个接口入口及其固定版本的官方脚本，来源见 [上一轮审计](2026-09-22-auto-refresh-beta9.md)。本次不改写第三方脚本或猜测其它学校的 SSO 地址。

| 类型 | 核对结果与处理 |
| --- | --- |
| 已带教务 SSO 地址 | 江苏大学 `/sso/jziotlogin`、广东技术师范大学 `/sso/lyiotlogin`、广州华立学院 `/sso/ddlogin` 已具有此类入口，保留。重庆化工职业学院、长春理工大学、广东工业大学、湖北汽车工业学院、江苏理工学院、喀什大学、上海中侨职业技术大学、南京师范大学、南方科技大学、天津城建大学、天津科技大学、郑州大学的 CAS service 参数也已经指向具体教务系统，保留。 |
| 门户登录不等于教务会话 | 重庆工程学院需到 `njw.cqie.edu.cn`；青海师范大学当前官方脚本要求 `https://yjsxt.qhnu.edu.cn`；南京邮电大学按 `/kbcx/`、`/xtgl/` 路径识别；江苏科技大学按 `/jwglxt/` 识别并保留 WebVPN 前缀；西北工业大学需到翱翔教务；广西医科大学需到 `jwxt.gxmu.edu.cn`。这些入口加入可见页面前置检查，实际成功仍以后台接口验证为准。 |
| 门户本身提供接口 | 不能仅因入口是门户或 WebVPN 就拒绝，例如湖南师范大学有门户 API 流程。继续使用官方入口及接口校验。 |
| Token 会话 | 沿用各校已审阅的存储字段白名单；修复安徽电气、北部湾大学 JWT 匹配正则转义错误。湖北汽车工业学院的页面变量 Token、重庆大学等学校的指定存储键继续恢复到原来源。 |
| 单页应用登录 | 可见浏览器监听已加载文档的 history 路由变化，避免登录页通过 hash / History API 切换后“读取登录态”一直不可用。 |

南京邮电大学官方说明区分校内教务入口与校外门户入口：[选课通知](https://jwc.njupt.edu.cn/2025/1224/c1594a295234/page.htm)。西北工业大学官方说明要求从门户进入翱翔教务：[新生教务说明](https://jiaowu.nwpu.edu.cn/info/1164/23888.htm)。因此不能把所有门户入口统一换成猜测的教务登录地址。

青海师范大学研究生院公开站点另有指向 `yjsgl.qhnu.edu.cn` 的旧认证链接，与当前固定脚本要求的 `yjsxt.qhnu.edu.cn` 不同；没有账号证据支持替换，保留官方适配器入口。黑龙江大学研究生入口依赖页面资源请求历史，宜宾学院含多页面操作，这类入口仍需对应账号及网络验证能否在新页面完整恢复；本次未据此宣称全部入口都已实测可用。
