# 托管 AI 配置池与导入默认外观

## 范围与数据路径

承接模型选择菜单恢复设置弹层动效。用户明确：后端下发多个供应商／模型配置，客户端直接请求供应商；失败时自动切换，AI 请求不经过 SleepDown 服务器转发。

- Bootstrap 增加配置列表，同时保留旧单配置字段；旧缓存和旧客户端格式继续兼容。显式空列表表示撤回配置，不退回旧单配置。
- 客户端逐项校验和解密，按优先级选择可用配置，单项损坏不阻塞其他配置。界面能力按候选集合展示，真正请求使用对应候选的能力。
- 托管请求在连接失败或 HTTP 401、403、404、408、429、5xx 时尝试下一配置，每项最多一次、总计最多八次。取消、普通参数错误、已开始输出或执行工具的请求不重放。
- 文件导入、文本导入、教务导入及助手对话复用切换策略。格式修复保留实际产出结果的配置，不换供应商重新上传原始文件。
- 私有后端支持独立发布多项配置和优先级，新版本只替换同一配置 ID 的旧版本。源码、管理配置、测试数据库及构建产物均保留在私有目录，没有加入公开提交，也没有部署。

## 空版本规则调查

没有复现“停用版本均留空却停用”的原始故障。代码与回归测试确认：最低版本为空且停用列表为空时不拦截版本；保存此空规则或清空既有规则不会把可用配置停用，也不会把未命中规则的停用提示交给客户端。

另外修正了按版本返回响应时的缓存边界：响应区分客户端 versionCode，禁用共享缓存；客户端不使用 URLConnection 缓存。控制台说明空规则即不限版本。不能将这个缓存风险直接认定为原故障的已证实根因。

### 免费额度误报的实际请求验证

用户另报所有入口提示“免费 AI 额度已用完”。确认客户端旧 `formatAiRequestError` 将所有 HTTP 429，以及响应中泛化匹配的 `quota`、`rate limit` 等文本，无条件改写为“今日共享额度已用完，请明天再试”。这个转换没有来自后端每日计数或重置时间的依据。现改为保留实际 HTTP 状态及服务响应，不虚构每日额度或恢复日期；自己的 Key 与托管 Key 使用相同的诊断原则，自动切换判定继续依照实际状态码。

按用户要求，在本机以 App 相同的签名证书、HKDF／AES-GCM 协议解密线上公开下发的配置，仅发送“请只回复 OK”。解密成功；线上配置版本 27、模型 `gpt-6-luna`、启用状态 true，实际 Responses 请求返回 HTTP 429，`error.type=rate_limit_error`，服务提示其所有可用账号当前受到限流。这证明这一次、这一组配置的请求不可用，不代表整个供应商均不可用，也不能推断 SleepDown 设置了每日额度。没有输出、保存或上传明文 Key；只将认证交给配置指定的服务。

检查时线上仅下发旧单配置字段，尚无配置池；本地后端的多配置改动未部署，不能声称该线上请求已有其他配置可自动接替。

此次错误提示修复另运行请求规范化和配置切换共 13 项定向测试，全部通过，覆盖 429、403、400、503 的实际诊断保留，以及取消／开始输出后不重放请求。

## 切页性能待定位

逐帧数据中，设置返回周视图的主线程尖峰出现在开始或结束附近，最高约 51 ms；日到周首帧主线程约 37 ms。用户随后确认使用性能档，取得的两轮设置返回、周到日、日到周采样均有长帧，P99 为 61–101 ms。

系统追踪首次因目录权限未启动；更换 Perfetto 专用目录后成功。第一段长追踪的环形缓冲只保留了末段约 8 秒，不能与前面的自动点击逐项对应。保留部分中仍能看到 App 的一次重组约 36 ms、紧随其后的布局约 21 ms，以及大量文字测量事件；需要完整短追踪与同场景帧数据复核。

核对本地 Compose Foundation 1.11.2 实际依赖字节码及 [AndroidX 实现](https://github.com/androidx/androidx/blob/androidx-main/compose/foundation/foundation/src/commonMain/kotlin/androidx/compose/foundation/text/modifiers/TextAnnotatedStringNode.kt)，`onTextLayout` 引用改变会清理段落布局缓存并要求重新测量。`CourseCardText` 与 `HomeReadableText` 的回调捕获当前对比度计算，冻结状态或阴影变化会更换回调。此次保持布局和位置回调的引用稳定，通过 `rememberUpdatedState` 读取最新计算，避免单纯视觉状态变化触发段落重排。文字内容、字体、宽度改变仍按原规则测量；两档材质参数、方向性高光和页面圆角裁切不变。

此处是已定位的重复工作，不据此提前宣称整体卡顿已经解决；安装后的同场景验证另行记录。
