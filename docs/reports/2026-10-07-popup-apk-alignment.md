# Popup APK 对照与材质修正

## 请求与证据

用户反馈前一版 Popup 与参考仍有差异，提供 Nexio APK，并要求降低描边亮度、缩短向侧边中段延伸的范围、删除材质内发光。随后明确仅首页个性化弹窗取消触发行压灰，其他页面保留。

- APK 元数据：`com.haooz.chedule`，版本名 `1.6.3-1004`，版本码 `163`。仅在本地读取，没有安装参考 APK。
- 通过 SDK `apkanalyzer` 读取 APK 的 `ListPopupLayoutKt` 动画参数和 `PopupPanelStyle` 几何计算，并对照 NexioSchedule `2daf4c387ecf298cc78df85004db88bb8d68fb7e` 中的 Popup 与 Dropdown wrapper。该提交的 Manifest 版本配置仍是相同值，不能根据版本名称判断 APK 的动画比最新源码旧。
- 前一版尺寸/锚点动画参数已一致，但用整层缩放近似回弹，缺少当前值及箭头的收起态内容，起点定位沿用下拉菜单位置，导致形变衔接与参考不同。本轮补齐几何与内容交接，而非继续微调相同曲线。

## 实现

- Popup 从当前值及箭头区域展开，宽高各自插值并保留真实过冲；固定采样画布每侧保留 14dp 回弹空间和 24dp 阴影外距，布局中只测量一次自然尺寸。
- 收起态的当前值、箭头保持原尺寸，随面板中心移动和淡出；原位置在弹层接管后隐藏这两个元素，关闭结束交还，标题保持原位。材质、收起态内容和菜单文字各自控制透明度。
- 保留进入 0.77/220、退出 0.85/650 的尺寸弹簧；独立锚点迁移使用 0.77/420 进入及 340ms `(0,0,0,1)` 退出。预测性返回取消用 150ms 恢复。
- 进度在绘制/图层阶段读取，0–6dp 文字模糊缓存并在静止时解除。触发行压灰恢复后，Morph 仍不启动旧的逐帧透明度观察。
- 公共 Popup 保留 10dp 背景模糊。移除持续的顶部表面渐变内发光；Kyant 手势光与形变反馈保留。描边峰值透明度从浅色 0.82/深色 0.48 降为 0.66/0.38，18%–82% 侧边范围透明。
- `showAnchorPressFeedback` 默认开启；首页个性化的文字排布入口显式关闭。该参数只控制外面触发行，不修改菜单内选中态。
- 更新第五份 Miuix 补丁，包含新增的 `OverlayListPopup` 收起态内容透传；不依赖忽略目录中的未导出修改。

## 验证

- 第五份补丁正向应用检查、对当前本地依赖的逆向检查及 `git diff --check` 通过。
- Popup 修改完成后 `assembleGithubRelease --no-daemon --console=plain --no-parallel --max-workers=1` 成功，耗时 7m07s，包含 Kotlin 编译、R8、资源处理、lintVital 和签名。
- ADB 5038 的设备列表及 mDNS 发现均为空，未安装或启动应用。
- 本轮以 APK 代码与源码比对为依据，尚无参考 APK 与本应用的实机逐帧画面对比，不宣称已完成视觉一致性验收。

## 追加：胶囊表头底部光

用户追加要求底部光覆盖得低一点，同时略厚一点。调整共用 `StatusPillContourLight`：彩色光开始淡入的位置由高度 35% 下移至 46%，白色底边的淡入区段同步下移；向内弥散宽度由 4.5dp 增至 5.2dp。保持原来的平滑羽化、真实圆角路径、峰值亮度和单次缓存网格绘制，不新增模糊层。追加后再次完成签名 `assembleGithubRelease`，耗时 6m26s。
