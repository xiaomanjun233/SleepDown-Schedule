# Agent 自检、确认界面与贡献流程

## 本轮实现

原角标、切周甩尾、编辑器圆角及 AI 教务识别修改见 [9 月 27 日报告](2026-09-27-badges-ai-edu-routing.md)。本轮继续在 `codex/badges-motion-ai-edu` 完成：

- 周视图普通卡片和编辑浮层共用日视图的文字颜色计算。白/黑文字由页面前景决定，彩色文字按页面背景调整，不再随卡片填充色独立反色。
- Agent 的 Chat Completions / Responses 共用工具解码和参数校验。未知工具、格式错误形成对应调用的失败结果；相同规范化调用只执行一次，修正参数后可重新调用。
- 能力按课程、作息、设置、调休、多课表、导航六个分区按需加载。新增原生 `PROPOSE_ACTIONS` 提交整份计划，自检通过后直接显示确认卡，数据库尚未写入。
- 本地自检覆盖 schema、真实课程、原周次与节次、目标范围、重复与互斥操作及预演。报错含动作序号、字段和原因，返回模型检查刚生成的计划并在本轮修正；旧正文计划也走同一检查。截断的数组或包装对象保留完整错误，不提取其中的个别动作。修正受六轮任务循环及最终一次修正上限约束。
- UPDATE/DELETE 支持 `sourcePeriods`，可只处理某周某节；预演和 Room 执行共用片段转换，保留未选中的周次、节次及逐节铃声。整体自定义时间无法可靠拆分时，报错返回模型，不能猜测单节时间。
- 确认卡按真实变更区分蓝色移动、红色删除、黄色重命名、绿色新增和紫色其他操作。课程、设置、作息、调休和多课表都有可读的内容与范围，课程显示修改前后差异。待确认内容保留原始事实快照；执行后禁用重复确认，保存时继续检查是否过期。
- 跨回合缓存预载最多12000字符、单项最多6000字符，大型有效快照按查询需要发送。操作说明不再每次全量发送；尚未测量真实供应商 token 和时延。

协议与数据边界详见 [Day Agent 运行规范](../architecture/DAY_AGENT_RUNTIME.md)。没有数据库迁移或备份格式变更。

## GitHub 贡献与主分支

用户要求保留项目主分支现有协作方式，因此维护者继续使用现有仓库与管理员权限，外部贡献走 Fork → PR → 审查；不强制分支命名、标题格式或 Issue 编号。

贡献文档、PR 模板、CODEOWNERS、路径检查和 Android 编译工作流已发布为独立 [Draft PR #57](https://github.com/xiaomanjun233/SleepDown-Schedule/pull/57)，目标 `main`，没有合并。此 PR 不含应用修复。管理员保护规则不收紧，新 CI 尚未设为必需检查。

主分支设置已修改并回读：保留至少一次批准、旧批准随新提交失效、禁止强推和删除；增加解决审查讨论及代码所有者审查。`enforce_admins=false`，维护者管理员流程保留。代码所有者的路径映射需 CODEOWNERS 合入 `main` 后生效。

GitHub plugin 的管理接口返回权限不足后，按用户要求检查既有连接：没有环境变量 Token，已有 Git Credential Manager 登录可用于该仓库管理。管理请求只在进程内使用该凭据，没有输出或保存凭据。常规 GitHub 元数据仍使用 Codex GitHub plugin，没有使用 GitHub CLI。

CI 使用 `pull_request`、只读仓库权限及公开依赖，不读取签名或模型凭据。实际运行中修正了已退役的 SDK tools 默认项和 Android 平台包名（`platforms;android-37.0`）；日志进一步定位阿里云镜像为 KSP 请求返回502，导致 Gradle 提前停止解析。新增仅 CI 启用的官方仓库选项，本地默认镜像顺序保留。
