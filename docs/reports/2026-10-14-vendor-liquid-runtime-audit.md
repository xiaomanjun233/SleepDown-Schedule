## 平板优先调查

修复将系统调用移入 Shizuku UserService；Root 命令和服务复用同一个防火墙实现。应用保留原状态日志、恢复闹钟和 finally 恢复，服务连接在后台有界等待，原生授权窗口仍由 Shizuku 管理。设置页监听 binder 到达/断开并刷新状态，权限请求在页面销毁或服务断开时清理监听。依据：[Shizuku 官方开发指南](https://github.com/RikkaApps/Shizuku-API)，UserService 不受应用进程的非 SDK API 限制。

壁纸原先从局部绘制区域选择横/竖屏裁剪，HD 侧栏和边距会改变局部宽高比；编辑预览还直接将 Context 转成 Activity，主题包装 Context 会落到手机比例。改为窗口方向与窗口实际比例，取色预览明确提供自身方向。两套保存字段保持原含义，没有迁移或交换历史用户裁剪值。

## 架构与性能判断依据

Google 建议以 UI、数据层和必要的领域规则划分职责，按功能组织可独立维护的模块；Compose 状态放在实际读写者的合适层级。它不要求每个文件对应一个 Gradle 模块，也没有一种目录结构能保证最高帧率。本项目继续使用已有分层和材质接口，避免为了拆分引入循环回调或改变动画生命周期。

- [Android 架构建议](https://developer.android.com/topic/architecture/recommendations)
- [模块化模式](https://developer.android.com/topic/modularization/patterns)
- [Compose 性能建议](https://developer.android.com/develop/ui/compose/performance/bestpractices)

当前已核实：SleepDown 和上述 Nexio 源码均采用共享壁纸模糊层、消费者采样缓存、无额外效果时的共享层直采，以及稳定层上的效果参数更新。共享 provider 并不消除每个仍有折射效果的 consumer 成本。SleepDown 还有课程轮廓光、形状变换、冻结背景、跨页面交接等路线；必须在相同可见内容、效果配置和设备上比较，不能仅凭文件数量或肉眼差异归因。

后续记录实际变更、提交、测试和设备证据。静态风险、可复现缺陷与性能测量结论分别说明。
